32  Python and R in one image

Learning Objectives

  1. Combine the uv and renv parts of a Dockerfile into one image that has Python and R
  2. Install software that is not a Python or R package, such as Quarto, in an image
  3. Run Python, R and Quarto in one container to render reports in both languages

Download the images before you start

The image in this chapter builds on the two images from Python packages with uv in an image and R packages with renv in an image. Start Docker first (on macOS and Windows, open Docker Desktop), then download (pull) them before you start:

Terminal
docker pull rocker/r-ver:4.6.2
docker pull ghcr.io/astral-sh/uv:0.13.7

32.1 The example project

Many data analyses use Python and R together, for example a Python script that cleans the data and an R script that fits a model. This chapter builds one image with both, from docker-uv-renv, the example project that the rest of this part of the book uses. Get a copy of it with Git:

Terminal
git clone https://github.com/chendaniely/docker-uv-renv.git
cd docker-uv-renv

Its Python packages are listed in pyproject.toml and locked in uv.lock, as in the uv chapter:

[project]
name = "docker-uv-renv"
version = "2026.11.13"
requires-python = ">=3.14"
dependencies = [
    "altair==6.3.0",
    "pandas==3.1.1",
    # Altair charts as images, for PDFs
    "vl-convert-python==1.9.0.post1",
    # Quarto needs these to run Python code
    "ipykernel==7.4.0",
    "nbclient==0.11.0",
    "pyyaml==6.0.3",
]

[tool.uv]
# `uv add` writes an exact version (==)
add-bounds = "exact"

Its R packages are listed in DESCRIPTION and locked in renv.lock, as in the renv chapter:

Type: project
Version: 2026.11.13
Description: The R packages this project uses. renv.lock locks them.
Depends:
    dplyr (== 1.2.1),
    ggplot2 (== 4.0.3),
    knitr (== 1.52),
    rmarkdown (== 2.32)

Its reports/ folder has two Quarto reports that make the same table and chart, report-python.qmd with pandas and Altair, and report-r.qmd with dplyr and ggplot2.

32.2 The Dockerfile

Here is the project’s whole Dockerfile. In this file, and in the project’s other files, ## starts a comment, and a single # switches off a line of code, which you can switch on by deleting the #:

## Ubuntu with R. Other versions:
## https://rocker-project.org/images/versioned/r-ver.html
## This base image alone: about 400 MB to download (compressed), 1.4 GB on disk.
FROM rocker/r-ver:4.6.2

## Python only, no R: plain Ubuntu (the version rocker uses) is much smaller,
## about 40 MB to download (compressed), 180 MB on disk.
## Swap the two FROM lines, and delete libuv1-dev and the R packages section below.
# FROM ubuntu:26.04

## libuv1-dev: the fs R package needs it (see renv::sysreqs())
RUN apt-get update && apt-get install --yes \
    curl \
    git \
    less \
    libuv1-dev \
    make \
    nano \
    openssh-server

## install quarto
## quarto comes with Typst for PDFs, so no LaTeX.
## dpkg --print-architecture: amd64 or arm64, to match your computer.
RUN curl --location --output quarto.deb \
    https://github.com/quarto-dev/quarto-cli/releases/download/v1.11.9/quarto-1.11.9-linux-$(dpkg --print-architecture).deb \
  && apt-get install --yes ./quarto.deb \
  && rm quarto.deb

## install python uv
## https://docs.astral.sh/uv/guides/integration/docker/#installing-uv
COPY --from=ghcr.io/astral-sh/uv:0.13.7 /uv /uvx /usr/local/bin/

## The project is mounted over /workspace, so the packages go in /opt
WORKDIR /workspace

## python packages in /opt/venv
ENV UV_PROJECT_ENVIRONMENT=/opt/venv
## ssh logins don't see ENV, only /etc/environment
RUN echo "UV_PROJECT_ENVIRONMENT=$UV_PROJECT_ENVIRONMENT" >> /etc/environment
COPY pyproject.toml uv.lock .python-version ./
## --locked: stop if uv.lock doesn't match pyproject.toml
RUN uv sync --locked

## R packages in /opt/renv/library
RUN echo "RENV_PATHS_LIBRARY=/opt/renv/library" >> /usr/local/lib/R/etc/Renviron.site
COPY renv.lock .Rprofile ./
COPY renv/activate.R renv/
RUN Rscript -e "renv::restore()"

## For linux laptops:
## StrictModes no: sshd wants root to own the key file,
## but on Linux the mounted one is yours
# RUN echo "StrictModes no" > /etc/ssh/sshd_config.d/container.conf

## -D: stay in the foreground, so the container keeps running
CMD ["/usr/sbin/sshd", "-D"]

Most of it comes from the two previous chapters. It starts from the R image, because rocker/r-ver has no Python:

Terminal
docker run --rm rocker/r-ver:4.6.2 bash -c 'command -v python3 || echo "no python3"'
Output
no python3

That does not matter, because uv installs the Python version in .python-version, as it did on top of Ubuntu. So the uv lines can be added to the R image unchanged:

  • FROM rocker/r-ver:4.6.2, the RENV_PATHS_LIBRARY line, the two COPY lines for renv and renv::restore() are the lines from R packages with renv in an image.
  • COPY --from=ghcr.io/astral-sh/uv:0.13.7, ENV UV_PROJECT_ENVIRONMENT=/opt/venv, the COPY line for uv and uv sync --locked are the lines from Python packages with uv in an image.
  • WORKDIR /workspace is in both.

The rest is new:

  • The apt-get line installs curl and libuv1-dev, as in the renv chapter. This project needs libuv1-dev because rmarkdown needs fs, through the packages bslib and sass. git, less and nano let you use Git, read files and edit files inside the container, make runs a Makefile (see Data analysis pipelines with GNU Make), and openssh-server lets you log in to the container over ssh.
  • The Quarto RUN line downloads Quarto 1.11.9 for your computer’s processor, installs it, and deletes the download. $(dpkg --print-architecture) runs dpkg --print-architecture and puts what it prints, amd64 or arm64, into the download address. Deleting the download in the same RUN line keeps it out of the image’s layers (see Building images). Quarto makes PDFs with Typst, which comes with it, so the image does not need LaTeX.
  • The line that adds UV_PROJECT_ENVIRONMENT to /etc/environment is for ssh. ENV applies to the commands Docker starts in a container, but a session that logs in over ssh reads /etc/environment instead.
  • CMD ["/usr/sbin/sshd", "-D"] makes a container run an ssh server when it starts, and -D keeps the server in the foreground, so the container keeps running. As in the earlier chapters, a command after the image name in docker run replaces it. Docker Compose starts this server, and a later chapter logs in to it.
  • The commented-out StrictModes no line is for Linux computers, where the ssh server refuses a key file that the mount makes yours, not root’s.

The order follows Building images. The steps that rarely change, such as installing software, come first, and the files that list packages are copied last, so that adding a package rebuilds only the steps after its COPY.

32.4 Use Python and R in one container

With the project folder mounted at /workspace, the same container runs Python with uv:

  • macOS and Linux
  • Windows (Git Bash)
  • Windows (PowerShell)
Terminal
docker run --rm -v "$(pwd):/workspace" docker-uv-renv uv run python --version
Terminal
docker run --rm -v "/$(pwd):/workspace" docker-uv-renv uv run python --version
docker run --rm -v "${PWD}:/workspace" docker-uv-renv uv run python --version
Output
Python 3.14.4

and R:

  • macOS and Linux
  • Windows (Git Bash)
  • Windows (PowerShell)
Terminal
docker run --rm -v "$(pwd):/workspace" docker-uv-renv Rscript -e 'R.version.string'
Terminal
docker run --rm -v "/$(pwd):/workspace" docker-uv-renv Rscript -e 'R.version.string'
docker run --rm -v "${PWD}:/workspace" docker-uv-renv Rscript -e 'R.version.string'
Output
[1] "R version 4.6.2 (2026-10-29)"

32.5 Render reports in both languages

uv run quarto render renders both reports. uv run starts Quarto with the project’s Python environment in /opt/venv, so Quarto runs the Python code with the packages from uv.lock, including ipykernel and nbclient, which Quarto needs to run Python code. R finds the packages from renv.lock in /opt/renv/library, because of the RENV_PATHS_LIBRARY line:

  • macOS and Linux
  • Windows (Git Bash)
  • Windows (PowerShell)
Terminal
docker run --rm -v "$(pwd):/workspace" docker-uv-renv uv run quarto render
Terminal
docker run --rm -v "/$(pwd):/workspace" docker-uv-renv uv run quarto render
docker run --rm -v "${PWD}:/workspace" docker-uv-renv uv run quarto render

The warning about TCP comes from the Python kernel that Quarto starts, which talks to Quarto over a network connection inside the container. Nothing leaves the container, so it does not matter here.
